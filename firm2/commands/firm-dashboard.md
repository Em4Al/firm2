# /firm-dashboard — показать дашборд

Аргументы `$ARGUMENTS`: имя change (необязательно; иначе активный).

```bash
ENGINE="$(node "${CLAUDE_PLUGIN_ROOT}/scripts/engine-root.mjs")"
node "$ENGINE/scripts/firm-event.mjs" dashboard
open .firm/dashboard.html
```

Первая строка пересчитывает состояние из журнала событий и перезаписывает файл,
вторая отдаёт его браузеру. Страница самодостаточна: ни сервера, ни сети не нужно.

Если `open` недоступен (не macOS, сессия без графики) — скажи человеку путь к файлу,
не пытайся показать содержимое в терминале: это 20 КБ разметки.

Дашборд **не обновляется сам** — это снимок на момент сборки. Спросили «что там
сейчас» во второй раз — пересобери и скажи, что страницу надо перезагрузить.

Покажи вдобавок текстовый срез, он часто отвечает на вопрос без открывания браузера:

```bash
node "$ENGINE/scripts/firm-state.mjs" board
node "$ENGINE/scripts/firm-event.mjs" doctor --json
```

Непустые `unknown` или `broken` в `doctor` назови вслух: это дыры в журнале, и
цифры тайминга при них неполны.

## Что на странице

- доска задач со статусами, зависимостями и SVG-графом;
- тайминг по задачам: календарное время против активного — разница есть ожидание,
  в первую очередь человека на воротах (`firm2-design.md` §4);
- баги по источнику;
- последние события журнала;
- **вкладка «Груминг»** — темы в разборе, сгруппированные по целевому выпуску (ADR-0012).
  Появляется только когда груминг есть: поставка без него видит прежний дашборд.
  По каждой теме — статус, где лежит досье, живо ли дерево, сколько в нём коммитов.

## Инварианты

- Команда только читает журнал и пишет сам файл дашборда. Состояние задач она не
  трогает: статусы правит `firm-event.mjs sync`, и это отдельное решение человека.
- `.firm/dashboard.html` в `.gitignore` — он перегенерируем, а при параллельных
  ветках давал бы конфликт на каждом слиянии (ADR-0003).
