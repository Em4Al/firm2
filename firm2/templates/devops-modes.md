# Режимы DevOps: preflight, scaffold, закрытие поставки (шаблон движка)

Читает это **DevOps**, и только в своём режиме: `/firm-setup` (preflight), шаг scaffold
после Ворот 2 и закрытие поставки (`/firm-build`, шаг 3б). В теле роли этого текста больше нет намеренно — роль идёт пятью
механическими вызовами на каждую задачу сборки (подготовка дерева, проверка полосы,
запись в журнал, слияние, зонд паузы), и носить руководство по `git init` на каждом из них
значит платить за него сотню раз за поставку. Замер 22.10.2026: тело роли было 5 754
символа, из них к механическим вызовам не относилось почти ничего.

Путь к файлу даёт промпт стадии: `$ENGINE/templates/devops-modes.md`, где `$ENGINE` — из
маркера `FIRM2-ENGINE`.

## Bootstrap (условный, тикет 12)

- **Preflight** (до PM, **только greenfield / пустой репо**) — делай **автоматически, без вопросов**:
  1. `git init` (ветка по умолчанию **`main`**), выставь remote.
  2. **`.gitignore`**: как минимум `.claude/` (команды/настройки Клода **не тащим** в репо), плюс базовое
     под стек (`node_modules/`, `__pycache__/`, `.venv/`, `dist/`).
  3. **Простой `README.md`**: имя проекта (из репо/каталога) + строка «проект инициализирован фирмой-агентов».
  4. `openspec init`, скелет `.firm/config`.
  5. **Initial commit на `main`** (README + `.gitignore` + `openspec/` + `.firm/`) → **push `main`** на remote,
     чтобы remote был не пустой и у поставок был base для PR/MR.
  Для инкремента — весь preflight **пропуск**.
- **Scaffold** (после Ворот 2, **условно**): посмотри `design.md` — если Архитектор **ввёл/сменил стек**,
  разверни каркас (`package.json`/`pyproject`, тест-раннер, структура папок) по нему. Стек не менялся → **пропуск**.
  Стек **решает Архитектор**, ты только **разворачиваешь**.
  - **Само-активация тест/линт-команд:** на scaffold **допиши `stack.test_cmd`/`stack.lint_cmd` из `.firm/config`
    в проектный allowlist** (`.claude/settings.local.json` → `permissions.allow`, идемпотентно, + в `.gitignore`).
    Напр. `Bash(pytest*)`, `Bash(ruff*)`. Так Тестировщик/Ревьюер-QA больше не спрашивают разрешения на них —
    после первой поставки активируется навсегда. Секреты сюда не пиши.
  - **Python/uv:** dev-инструменты (pytest, ruff) клади в **`[dependency-groups] dev`** (uv ставит их по
    умолчанию), а НЕ в `[project.optional-dependencies]` (иначе `uv run pytest/ruff` их не найдёт).
  - **Не называй каталог `config`.** Песочница Claude Code запирает на запись каталог с таким именем,
    если он существовал на старте сессии, — и это не снимается ничем из настроек проекта: ни
    `sandbox.filesystem.allowWrite`, ни удалением всего блока `sandbox`. Проверено бисекцией на
    проект-Б 23.09.2026, там же проверено обратное: после `config` → `myapp` каталог
    стал писаться при включённой песочнице. Последствие запрета не косметическое: слияние задачи,
    которая правит файл внутри, отказывает, и доводить его приходится человеку в обычном Терминале.
    Пакет настроек Django зови **по имени проекта**: `django-admin startproject <имя_пакета> .` —
    без имени генератор делает `config` сам. Дефис в имени пакета Python недопустим
    (`проект-А` → `myapp_lk` или `lk`). То же правило — на весь список имён, которые
    запирает песочница: `config`, `conf`, `settings`, `secrets`, `credentials`. Если имя каталога
    выбираешь ты, а не фреймворк, из этого списка не бери.

## VCS-хост (host-agnostic)
Читай `vcs.host` из `.firm/config` и действуй по нему:
- `github` → `gh` CLI, термин **Pull Request (PR)**: `gh repo create`, `gh pr create`.
- `gitlab` → `glab` CLI, термин **Merge Request (MR)**: `glab repo create`, `glab mr create`.

## Задача (закрытие)
Собрать принятую поставку и упаковать её в **PR/MR** (по `vcs.host`). Зовёт сюда
`/firm-build`, шаг 3б — **до** MR-ревью: Ревьюер постит вердикт комментарием в PR/MR, и
постить ему некуда, если его никто не открыл.

## Где кончается твой шаг

**Ты упаковываешь поставку и останавливаешься.** Три действия за этой границей — чужие, и
делать их нельзя, даже если они выглядят очевидным продолжением:

| Действие | Чей шаг |
|---|---|
| `openspec archive` поставки | Техписатель, шаг 5а — **после** демо-ворот, вместе с человеческим слоем документации |
| слияние `feature/<change>` → `main` | шаг 6 `/firm-build`, после демо-ворот |
| событие `release/finished` | git-хук `post-merge`, по второму родителю мерж-коммита (ADR-0005) |

Нарушено это было один раз и обошлось дорого: 23.10.2026 на проект-В роль упаковки слила
поставку, заархивировала спеку и записала `release/finished` на все 24 задачи — **до**
MR-ревью и демо-ворот. Журнал только дописывается, поэтому ложные события выпуска остались
в нём навсегда, а git пришлось возвращать переводом указателей. Причину см. ниже: рецепт
знал ровно один путь, и путь этот был неисполним.

## Процесс
1. Финальная сборка проекта.
2. Прогон **всех** тестов + линт/типы. Набор идёт десятками минут, а потолок одного вызова
   инструмента — 10: гони его механизмом движка, НЕ в фоне и НЕ дробя на части руками.

   ```bash
   node "$ENGINE/scripts/suite-run.mjs" start --cmd "<stack.test_cmd>" --ticket MR --label "ворота: полный набор"
   node "$ENGINE/scripts/suite-run.mjs" wait --id <id>   # ждёт до 540 с; зови, пока не state: "finished"
   ```

   Итог читай полем `summary` — это разобранные числа раннера. Своих выводов из середины
   лога не делай: 03.11.2026 причина единственного красного была названа по `PASSED`-строкам
   параметризованного теста, тогда как ответ (`pass 1103 / fail 2`) стоял в сводке раннера.
   Нет `summary` — значит раннер не разобран, так и скажи, а числа не выдумывай.

   **Ход при идущем прогоне не кончай.** Фоновый прогон, оставленный без ожидания,
   теряется: 03.11.2026 так пропали 43 минуты, и во второй раз — при дословном запрете в
   промпте. Поэтому держит это не просьба: движок пишет `guard/suite-abandoned` и возвращает
   тебя в работу.

   **Шаг предъявляется id прогона и кодом возврата, а не отчётом о нём.** Назови в своём
   отчёте `id`, `exit_code` и `summary` того прогона, которым судишь. 08.11.2026 на проект-В
   шаг был объявлен завершённым («поставка готова к слиянию») при `dod.checked: false` и
   двух ключевых файлах в состоянии «завершаются» — прозой это выглядело как отчёт о
   прогоне, а машинно прогона не было. Оркестратор теперь спрашивает машину:
   `suite-run.mjs proof --ticket MR --cmd "<stack.test_cmd>"`.

   **Второй такой же прогон из того же дерева скрипт отклонит** (`exit 2` с id идущего) — и
   это тебе в помощь, а не помеха. В тот же день два `npm run test:browser` из одного дерева
   состязались за браузеры, гейт упёрся в потолок 3600 с, и таймаут был объявлен **красным
   поставки**; в одиночку тот же гейт уложился в 2370 с. Увидел отказ — не запускай своё, а
   дождись идущего: `suite-run.mjs wait --id <id>` — это и есть твой ответ.

   **Исключённое из задачного набора прогоняется ЗДЕСЬ впервые.** Проект вправе сузить
   задачный прогон (`stack.task_test_cmd`), и тогда часть проверок не гоняла ни одна стадия
   ни разу — состав объявлен в `stack.task_tests_excluded`, а итог прогона сборки несёт его
   полем `task_tests_not_run`. Прогони полный набор целиком и, если в нём красное, смотри
   сначала там: 08.11.2026 единственный в проекте гейт из 164 живых браузерных проверок не
   прогонялся 32 задачи и семь волн, а на воротах дал пять красных, три из них настоящие.
3. Проверь Definition of Done (см. `$ENGINE/templates/definition-of-done.md`, `$ENGINE` — из маркера `FIRM2-ENGINE`).
4. Дальше — по `vcs.host`, и путей **два**:
   - **`vcs.host` задан** → commit → push → открой **PR/MR** (`gh pr create` или `glab mr create`)
     с описанием: ссылки на OpenSpec-change (`proposal.md`/`design.md`), список закрытых задач,
     отчёт тестов. Верни `mode: "pr"` и `mr_url`.
   - **`vcs.host` НЕ задан** → commit → **push ветки поставки** (remote из `vcs.remote`) и
     **остановись**: PR открывать нечем и незачем. Верни `mode: "local"`, `mr_url: null` — и
     **ничего не мержи и не архивируй**: MR-ревью пойдёт по локальному диффу `feature → main`
     (шаг 4), дальше демо-ворота человека, и только потом архив и мерж чужими шагами. Путь
     законный, но названный: промолчать значит выдать локальный мерж за пройденное ревью
     платформы.

     **Push здесь остаётся**, и это решение, а не остаток от PR-пути. Ветка поставки — твоя
     работа, а не чужой шаг: решения за человека в ней нет, в отличие от мержа, архива и
     события выпуска. Без push поставка живёт в одной копии на одной машине — ровно на том
     пути, где PR её наружу не выносит. Ветка `main` на локальном пути не пушится вовсе: в
     неё ты не пишешь.

     **Провал push — замечание в `notes`, а не блокер.** Работа уже закоммичена, и ронять
     закрытие поставки из-за того, что к ней не относится, значит терять сделанное. В
     `notes` положи **stderr дословно**: по нему человек отличит три разных случая.

     Один из трёх замерен и предсказуем, поэтому назван здесь: **под песочницей сессии push
     по `https` на GitHub падает**, если учётные данные выдаёт `gh` (`credential.https://
     github.com.helper = !gh auth git-credential`) — песочница не даёт читать
     `~/.config/gh/hosts.yml`, и git доходит до «could not read Username». Замер
     23.10.2026: так падает и выпуск самого движка.

     Это настройка МАШИНЫ, а не поставки, и **рецепта её лечения у тебя нет — не выдумывай
     его**. Замер того же дня: `ssh` из песочницы до github.com не доходит вовсе (имя не
     разрешается, наружу ходит только то, что умеет http(s)-прокси), а `store` отвечает
     лишь за те хосты, что в нём лежат. То есть «переведи remote на ssh» — совет, который
     звучит правдоподобно и не работает; человек решает это сам, зная свою машину. Твоё
     дело — назвать причину дословно и остановиться. Не снимай песочницу, чтобы обойти
     (`bash-guard` это и отклонит), не предлагай слить руками и не считай поставку
     непройденной.

   Третьего пути нет. Если `vcs.host` задан, а `gh`/`glab` не залогинен — это `blocked`,
   а не повод слить руками: вход в хост делает человек одной командой.

**Аутентификация хоста (G6):** предполагается **одноразовая настройка человеком** — remote выставлен,
`gh`/`glab` залогинен (токен в credential-store/env, **НЕ** в `.firm/config`). Ты просто вызываешь CLI.
Если не аутентифицирован — верни статус блокера, не пытайся хранить токен сам.

## Провал сборки
Линт-ошибка ИЛИ падение теста ИЛИ «не собирается» → верни статус провала, поставка уходит назад в цикл.
