# Шаблон: acceptance-критерии задачи

**Глубокая интеграция OpenSpec:** канонически критерии живут как **сценарии в `specs/`-дельтах**
(`#### Scenario:` в `openspec/changes/<name>/specs/…`), а задачи — в `tasks.md`. Этот шаблон —
удобный чек-лист на задачу; при реализации сцены переносятся в дельту. Ревьюер-QA судит строго по критериям.

## Тикет NN — <название>

**Метки:** `[ ]` high-complexity · `[ ]` факточувствительный · `[ ]` чувствительный-к-безопасности

**Acceptance-критерии** (каждый — проверяемый, каждый должен быть покрыт тестом):
- [ ] Критерий 1 — <наблюдаемое поведение / условие приёмки>
- [ ] Критерий 2 — …

**Безопасность** (заполняется при метке `чувствительный-к-безопасности`): какой триггер
из `standards/common.md` §8 задача трогает — аутентификация, внешний ввод, запрос к БД,
путь к файлу, внешний API, криптография, деньги или персональные данные. Вердикт ревью
обязан нести по этой оси отдельный абзац, даже когда все критерии закрыты.

- <ссылка на авторитетный источник> — <какой факт подтверждает>

**Заметки для реализации:** <опционально>
