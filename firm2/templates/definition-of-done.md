# Шаблон: Definition of Done (поставка)

DevOps сверяется с этим чек-листом перед открытием PR/MR. Поставка готова, когда:

- [ ] Код + тесты в git-репо (remote — GitHub/GitLab).
- [ ] **Все тесты зелёные** + **каждый acceptance-критерий покрыт тестом** (критериальное покрытие).
- [ ] Линт/типы чисты **по политике** (`lint-policy.md`), проект собирается.
      «Чист» — не «не осталось находок любой ценой»: правило, спорящее с фреймворком,
      языком или осознанно принятым стилем, гасится в конфиге с причиной.
- [ ] **Стандарты кода** (`docs/standards/`): ревью вынесло суждение по оси Standards со
      **ссылкой на правило**. Стандартов в проекте нет — ось объявлена непроверенной, а не
      пройденной (ADR-0007).
- [ ] **Безопасность кода:** ни одного секрета в диффе (проверяет хук `secret-scan`, и он
      видит только образцы — смысл видит ревью). По каждой задаче с меткой
      `чувствительный-к-безопасности` в вердикте есть отдельный абзац по оси безопасности:
      инъекция склейкой строк, непроэкранированный вывод, обход пути, ветка без проверки
      прав, утечка токена или персональных данных в лог (`standards/common.md` §8).
- [ ] README с инструкцией запуска («клонируй → запусти») + запускаемый артефакт.
- [ ] Изменение оформлено как OpenSpec-change (`openspec/changes/<name>/`: `proposal.md`/`design.md`/`tasks.md`/`specs/`-дельты).
- [ ] **Документация (SDD/OpenSpec):** `openspec archive <name> --yes` выполнен — снимок в
      `openspec/changes/archive/YYYY-MM-DD-<name>/` (иммутабельно), живые `openspec/specs/` обновлены;
      `openspec validate --specs` зелёный (**без `--all`**: `--all` валидирует ещё и
      активные поставки, и проверка краснеет от чужой работы);
- [ ] **Человеческая дока** (`docs/` по Diátaxis, приём `firm-human-docs`): либо обновлена,
      либо названа причина, почему поставка её не затронула.
- [ ] Выдача = один **PR/MR**: ссылки на change/specs, список закрытых задач, отчёт тестов.

**Провал сборки** = линт-ошибка ИЛИ падение теста ИЛИ «не собирается» → возврат в цикл.
Линт-ошибка разбирается по `lint-policy.md`: правило про поведение чинится всегда,
оформление — по месту находки.
