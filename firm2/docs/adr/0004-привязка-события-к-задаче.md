# ADR-0004. Событие привязывается к задаче маркером в промпте, а не идентификатором агента

- Статус: принято
- Дата: 2026-10-01
- Контекст: обкатка на четырёх проектах; уточняет ADR-0002

## Контекст

События стадий пишет hook по сигналам `SubagentStart`/`SubagentStop` (ADR-0002). Хук
знает роль субагента — отсюда выводится стадия, — но не знает, над **какой задачей** тот
работал. Без этого событие бесполезно: оно не попадает ни на доску, ни в тайминг, а
`doctor` считает его дырой.

Рассматривались три источника привязки:

1. Идентификатор агента от рантайма (`CLAUDE_AGENT_ID`) — субагент объявляет себя сам,
   записывая файл заявки перед работой.
2. Маркер `FIRM2-TICKET: T-XXX`, который workflow-скрипт кладёт в промпт каждой стадии;
   хук читает его из полезной нагрузки.
3. Собственный транскрипт субагента: промпт стадии написан кодом, значит маркер лежит в
   первой строке файла `agent-<id>.jsonl`.

## Решение

**Истина — маркер в промпте (2), с достройкой по транскрипту (3).** Вариант (1)
отвергнут: рантайм идентификатор субагенту **не передаёт**.

Это проверено, а не предположено: механика заявки прожила несколько версий, и за тридцать
с лишним стадий на реальном прогоне каталог `.firm/current/` остался пустым. Код заявки
удалён, а строка про неё убрана из промпта — мёртвая инструкция в промпте хуже
отсутствующей, потому что выглядит работающей.

Достройка по транскрипту нужна для момента, когда событие уже записано, а полезная
нагрузка маркера не содержала (это бывает на `SubagentStop`): по `agent_id` открывается
первая строка транскрипта и маркер читается оттуда. Результат помечается
`_ticket_from: 'transcript'`, и `doctor` показывает, сколько событий держится на этой
связи.

## Обоснование

- Маркер пишет **код**, а не модель: роль не может его забыть, переформулировать или
  пересказать по-своему. Это та же линия, что в ADR-0002.
- Привязка не зависит от того, что рантайм решит отдать субагенту завтра.
- Транскрипт — последний рубеж, который работает даже тогда, когда полезная нагрузка
  пуста: файл промпта существует всегда, иначе стадии бы не было.

## Следствия

- **Маркеры из промптов не убирать.** Без них событие уходит в журнал с `ticket: unknown`,
  и хук возвращает `exit 2`.
- Стадия уровня поставки (ревью всего диффа) привязывается меткой `MR`: задачи с таким
  номером нет, а событие есть. На доску `MR` не попадает.
- Заглушка `T-XXX` из шаблонов распознаётся и отбрасывается: она уже уезжала в журнал
  привязкой к несуществующей задаче.
- Открытая стадия без привязки — не дыра, а норма момента: пока стадия идёт, взять тикет
  неоткуда. `doctor` разделяет эти случаи по возрасту события.
