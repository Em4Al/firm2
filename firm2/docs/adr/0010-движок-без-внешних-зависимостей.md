# ADR-0010. Код движка — без внешних зависимостей; инструменты проверок — только в разработке

- Статус: принято
- Дата: 2026-09-21, уточнено 2026-10-01
- Контекст: выбор рантайма для скриптов движка

## Контекст

Скрипты движка (`scripts/*.mjs`, около 4,5 тысяч строк) читают файлы, зовут git, считают
журнал и собирают HTML. Всё это делается либо на стандартной библиотеке Node, либо с
пакетами: разбор YAML, шаблонизатор, работа с git, генератор графов.

Обстоятельство, решающее дело: Node в проекте **гарантирован** — его требует OpenSpec,
без которого маршрут не работает вовсе. А вот `npm install` в проекте пользователя не
гарантирован ничем: сеть, прокси, права на кэш.

## Решение

**В `scripts/` и `workflows/` — ноль внешних зависимостей.** Разбор frontmatter, YAML-подмножества
конфига, сборка HTML и работа с git написаны руками на стандартной библиотеке.

Уточнение 01.10.2026: **инструменты проверок — исключение, но только в разработке.**
`eslint` и `codegraph` стоят в репозитории движка, а не в проектах: `node_modules/` и
`.codegraph/` в `.gitignore` и в кэш плагина не копируются (ADR-0008). Проект, читающий
движок по `engine_root`, не должен ничего устанавливать — и не устанавливает.

## Обоснование

- Доставка плагина — копирование каталогов. Зависимость в `scripts/` означала бы шаг
  установки в каждом проекте, и первый же сбой сети превращал бы движок в неработающий.
- Движок зовётся из hook-ов и из стадий сборки, то есть в момент, когда отлаживать
  установку пакетов некому.
- Цена — несколько десятков строк разбора конфига. Она заплачена один раз.

## Следствия

- Разбор конфига поддерживает **подмножество** YAML, а не YAML. Это осознанно; при
  расширении конфига проверять надо разбор, а не надеяться на него.
- Проверки движка требуют `npm i` **в репозитории движка**. На этой машине — с обходом
  сломанного кэша npm: `npm i --cache "$TMPDIR/npm-cache"`.
- Рубеж `preflight.mjs` помечает шаг линтера пропущенным, если `node_modules` нет: так
  видно, что проверка не выполнялась, а не что она прошла.
