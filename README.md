# firm2 — маркетплейс плагина Claude Code

Фирма-команда агентов-разработчиков для Claude Code: восемь ролей, десять приёмов,
маршрут из трёх сессий `/firm-discovery` → `/firm-plan` → `/firm-build`, двое
человеческих ворот, параллельная сборка задач в отдельных git worktree и
детерминированный журнал переходов, из которого считаются статусы, тайминг и цена
стадий.

Подробности реализации — [`firm2/README.md`](firm2/README.md), замысел и
обоснования — [`firm2/docs/firm2-design.md`](firm2/docs/firm2-design.md),
трудно-обратимые решения — [`firm2/docs/adr/`](firm2/docs/adr/), схемы маршрута —
[`firm2/docs/how-it-works.md`](firm2/docs/how-it-works.md).

## Установка

```
/plugin marketplace add Em4Al/firm2
/plugin install firm2@firm2 --scope user
```

`--scope user` ставит плагин один раз на аккаунт, и он виден из любого проекта.
Команды и роли подтягиваются **в новой сессии**: в текущей в контексте остаются
описания, загруженные при старте.

Дальше — в своём проекте, в новой сессии:

```
/firm-setup
```

Эта команда заводит `.firm/config`, ставит git-хук `post-merge`, проверяет линтер и
тесты, согласует границы песочницы и собирает граф кода. Без `.firm/config` и хука
`post-merge` журнал событий не ведётся, а на нём держится весь маршрут. Повторный
запуск безопасен и служит проверкой.

## Что нужно кроме плагина

- **Node.js** — движок написан без внешних зависимостей (ADR-0010), так что ничего
  ставить не надо. Разработка самого движка требует `eslint` (`npm i` в корне).
- **[`mattpocock-skills`](https://github.com/mattpocock/skills)** — на нём стоят
  семь приёмов-адаптеров из десяти (`firm-tdd`, `firm-review`, `firm-research`,
  `firm-interview`, `firm-design`, `firm-domain-model`, `firm-docs`). Без набора
  эти приёмы не работают:
  ```
  claude plugin marketplace add https://github.com/mattpocock/skills.git
  claude plugin install mattpocock-skills
  ```
- **`@fission-ai/openspec`** — нужен для `openspec init` и SDD-документации.
- **`@optave/codegraph`** — не обязателен. `/firm-setup` спросит, ставить ли, и
  запишет отказ в конфиг; без графа MR-ревью лишается `diff-impact`.

## Состояние

Движок **обкатывается**. Код написан 21.09.2026, дефекты прогонов разбираются и
исправляются — летопись в [`firm2/CHANGELOG.md`](firm2/CHANGELOG.md). Что проверено
живым прогоном, а что нет, — в `firm2/README.md`, раздел «Что проверено, а что нет».
Это рабочий инструмент одного автора, выложенный как есть; обратной совместимости
между версиями не обещается.

## Про имена проектов в обоснованиях

У движка есть правило: порог, число или механизм обязаны ссылаться на то, где это
замерено. Поэтому в комментариях кода, промптах ролей и CHANGELOG рядом с числами
стоят имена проектов, на которых движок обкатывался. В публичной версии они
обезличены — **проект-А**, **проект-Б**, **проект-В**, **проект-Г**, **проект-Д**.
Это живые разные проекты; даты, числа и выводы замеров на месте, заменены только
имена.
